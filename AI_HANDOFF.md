## Project at a glance

Hindu Companion is a **static Astro 4 site**. It has no application server, database, account system, analytics, or runtime API. GitHub Pages publishes the static `dist/` output after quality checks pass.

- Current GitHub Pages preview URL: `https://avyanbhattacharya.github.io/hindu-companion/`
- Intended custom domain: `https://hinducompanion.com` (DNS/custom-domain verification is not yet complete)
- Node version: 24 or later
- Build command: `npm run build`
- Production build output: `dist/`

## Required setup and checks

Run these in this order before handing work back:

```bash
npm ci
npm run test:static
npm run build
npx playwright install --with-deps chromium webkit  # once per new environment
npm run test:browser
```

Do not edit `package-lock.json` by hand. If dependencies genuinely change, update `package.json`, regenerate the lockfile with npm, then run all checks. Avoid adding dependencies unless the requested feature clearly requires one.

## GitHub Pages URL rule — very important

The current Pages site is hosted below `/hindu-companion/`, not at the domain root. It will later also be available on a custom domain. Therefore:

- Use **relative internal links** such as `bhajans/`, `../guides/`, and links generated by existing components.
- Do **not** write domain-root links such as `href="/bhajans"` or `href="/guides/ekadashi"`.
- Keep `build.format: 'directory'` in `astro.config.mjs`; generated routes must be directories with `index.html`.
- Any navigation change needs browser coverage for the GitHub Pages subpath and mobile WebKit.

## Content and spiritual-care rules

1. Do not invent festival dates, tithi, sunrise times, parana windows, quotations, authorship, translations, scripture references, or religious claims.
2. The calendar is intentionally a roadmap until a reviewed data source and calculation policy are selected. Do not turn it into a live panchang with example data.
3. Every new Markdown entry needs complete frontmatter, especially `source` and a truthful description.
4. Do not copy copyrighted lyrics, translations, recordings, images, or text from websites without documented permission or a clear public-domain/right-to-reuse basis.
5. Keep language respectful and inclusive. Clearly distinguish a tradition-specific practice from a universal Hindu practice.
6. Do not add external fonts, analytics, trackers, APIs, embeds, or network calls unless explicitly requested and approved.

Read `docs/CONTENT-GOVERNANCE.md` before adding any devotional content.

## Design rules

- Preserve the calm, devotional, mobile-first style.
- Use the CSS variables in `src/styles/theme.css`; do not scatter replacement color values across pages.
- Keep the ornamental `hero::after` element non-interactive (`pointer-events: none`). It previously blocked taps in mobile WebKit.
- Use semantic HTML, visible focus states, readable contrast, and screen-reader labels for controls.
- Avoid a crowded poster-like layout. Prefer clean whitespace, concise cards, and readable Hindi/Bangla/Sanskrit text.

## Testing expectations

- Static tests verify Astro configuration, required content provenance, and visual-token structure.
- Browser tests run in Chromium, desktop WebKit, and mobile WebKit.
- Browser tests must not rely on external network requests.
- Test actual user behavior, not merely the presence of source code.
